## Known quirks (full notes, 2026-10-06)

- **Cloud sessions** (claude.ai/code): the session edits a clone on a remote machine, so Azul and the user's Studio never see it, and the Roblox MCP can't connect (it needs the user's PC). Work reaches Studio by `git push` (the Claude GitHub app needs write access) and the user's `git pull` (with Azul running, it carries the files into Studio). **But Azul only updates scripts that already exist in Studio:** a file new to `sync/` logs "No mapping found" and never arrives, and whatever `WaitForChild`s it hangs (2026-10-03: the HUD, TycoonFX, ProductionVisuals and RoomFX waited forever on 5 new modules). So a cloud session that adds files also runs `python3 tools/studio_upsert.py --since <the commit it started from>`, commits the generated `tools/AddNewScripts.luau`, and tells the user to paste all of it into Studio's Command Bar (Edit mode) once after pulling: it creates (or updates) each script in place with the right class; Azul maps them from then on. (Checked with Lune against a fake `game`: every script's source matches its file.) Type-check there with the Linux luau-lsp: `LUAU_LSP=... LUAU_DEFS=... sh tools/typecheck.sh` (it builds the sourcemap from `sync/` when Azul's is missing). Geometry: `tools/lab`.
- **Characters spawn only after the world is built** (`Main.server`: `CharacterAutoLoads` is off until MapBuilder.Init returns). Code that builds over several frames uses `WorkBudget.Step()` only where yielding is safe.
- **The MCP can't require modules or invoke `DevCommand` any more** (since 2026-10-02: "The current thread cannot require/invoke ... additional values for the Capabilities property"). It can still read the game, set attributes and make parts. `DevTools` listens to workspace's `DevRequest` attribute instead: on the Server, `workspace:SetAttribute("DevRequest", '["Snapshot"]')`, then wait for `DevResult` (`{"ok":true,"result":...}`). `SetPurchasedList` buys several items with one rebuild: `HttpService:JSONEncode({ "SetPurchasedList", { "ClayStudio_Room", "ClayStudio_1_Line" }, true })`. A freshly bought edition pops a "NEW EDITION!" panel: hide `PlayerGui.BrainrotUI` for screenshots, then turn it back on.
- **`screen_capture` doesn't show AlwaysOnTop BillboardGuis** (the brainrots' name tags): before a shot, set `AlwaysOnTop = false` on the BillboardGuis under `workspace.Effects` (and on new ones, with a `DescendantAdded` hook).
- **Azul can die silently** (2026-10-03: no `node` process; every edit after a point never reached Studio, and Studio kept old art). Restarting it (`azul` in the repo, a global npm command) waits for the Studio plugin to connect, and on connect it rewrites `sync/` from Studio: **commit first**. If the plugin won't connect, the MCP can push files into Studio itself: serve the repo with `python -m http.server 8765 --bind 127.0.0.1`, then in Edit set `HttpService.HttpEnabled = true` for the moment, `GetAsync` each file and write it with `ScriptEditorService:UpdateSourceAsync` (strip `
`), and set `HttpEnabled` back (done for the 15 art files; checked in a playtest).
- **Never `git stash`/`checkout` while Azul runs:** Azul pushes the disk into Studio, so a stash puts old code in Studio, and an untracked file it removes deletes that module in Studio (it happened to `Config/LineUpgrades`; restored).
- **ProductionVisuals is near the 200-locals limit too** (196 top-level locals since 2026-10-03: adding `Mover` broke the client with "Out of local registers"; the luau-lsp type check and Lune's compiler don't catch it). Modules it uses once are required where they're used; add no new top-level locals there (put new things in a table or module).
- **TycoonManager is at Luau's limit of 200 locals** in one function (its main chunk): the server failed to start with "Out of local registers" when the stations were added. Put new builders in their own modules (`StationBuilder`, `RoomUpgradeBuilder`), or group constants in tables.
- **`screen_capture` hangs when Studio isn't rendering** (behind other windows or the user away from the PC): the call never returns and the user thinks the session froze. With Studio **minimized** it returns a white image with only the CoreGui (2026-10-02): check `IsIconic` on its window (PowerShell, user32) before blaming the camera. Studio under VS Code (not minimized) renders fine. A normal capture returns in 2–10 s. Before a capture, make sure Studio is rendering (ask the user), and prefer data probes; build previews in Edit (e.g. `FactoryBuilder.Build` into a Model far from the map, then delete it) when only the look matters. - **Destructive tests: always Restore before the playtest stops.** The DevTools snapshot lives in the test server's memory; if the playtest ends first (it did when the user's usage limit hit, and when Studio ran out of memory), the test state gets saved.
